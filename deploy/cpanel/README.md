# BizMonitor — cPanel სერვერი

ეს ZIP შეიცავს მხოლოდ აწყობილ სერვერს. iPhone-ის აპი და Mac-ის მონაცემები მასში არ შედის.
სერვერი იღებს მიმდინარე iPhone აპის `/api/v1/local/...` მოთხოვნებს და პროფილებს, დაშიფრულ პაროლებს, RS-ის ბოლო პასუხებსა და შეტყობინებებს MySQL-ში ინახავს.

## 1. ჰოსტის მოთხოვნები

- Node.js **24 ან უფრო ახალი** (შემოწმებულია Node 24-ზე); MySQL 8 ან თავსებადი MariaDB, InnoDB და utf8mb4.
- დომენი HTTPS სერტიფიკატით; API ცალკე ქვედომენის ფესვზე, მაგალითად `https://api.domain.ge`.
- Puppeteer-ის Chrome-ის გაშვების უფლება, საჭირო Linux სისტემური ბიბლიოთეკები და გამართული sandbox.
- გამავალი HTTPS წვდომა `eservices.rs.ge`-ზე და RS-ის SOAP სერვისებზე.

მხოლოდ „Setup Node.js App“-ის არსებობა Chrome-ის მხარდაჭერას არ ადასტურებს. თუ ჰოსტი Chrome-ს არ უშვებს, API და MySQL იმუშავებს, მაგრამ RS-ის ვებკაბინეტიდან თანხებისა და შეტყობინებების მიღება ვერ იმუშავებს. ჰოსტინგმა უნდა დააყენოს საჭირო სისტემური ბიბლიოთეკები/მოგცეს შესაბამისი გარემო. sandbox-ის ავტომატური გამორთვა ამ პაკეტში არ ხდება.

## 2. ZIP-ის ატვირთვა

1. cPanel-ში შექმენი MySQL ბაზა და მომხმარებელი. მომხმარებელს მიეცი ამ ბაზაზე ALL PRIVILEGES. გამოიყენე cPanel-ის სრული სახელები, მაგალითად `account_bizmonitor`.
2. File Manager-ში ატვირთე და გაშალე ZIP კერძო აპლიკაციის საქაღალდეში, მაგალითად `/home/ACCOUNT/bizmonitor-api`, **public_html-ის გარეთ**. ამ საქაღალდეში პირდაპირ უნდა ჩანდეს `app.js`, `package.json`, `dist/`.
3. Setup Node.js App-ში აირჩიე Node 24+, Production, Application root = ეს საქაღალდე, Application URL = შენი HTTPS ქვედომენი, Startup file = **app.js**.
4. დააყენე ქვემოთ ჩამოთვლილი Environment variables. ალტერნატივაა `.env.example`-ის `.env` სახელით დაკოპირება აპის კერძო საქაღალდეში და შევსება (chmod 600). cPanel-ის Environment variables ფაილზე პრიორიტეტულია.
5. Run NPM Install ან cPanel-ის მიერ ნაჩვენები Node გარემოს Terminal-ში გააქტიურების შემდეგ `npm ci --omit=dev`. სერვერის თავიდან დაბილდვა საჭირო არ არის. არ ატვირთო Mac-ის node_modules.
6. Restart Application. სერვერი ცხრილებს თვითონ ქმნის; სურვილის შემთხვევაში `schema.sql` წინასწარ შეიტანე phpMyAdmin-ში, არჩეულ ბაზაში.

## 3. გარემოს ცვლადები

| სახელი | რა ჩაწერო |
|---|---|
| NODE_ENV | `production` |
| PUBLIC_ORIGIN | შენი რეალური `https://api.domain.ge`, `/api/v1`-ისა და სხვა გზის გარეშე |
| CONNECTION_KEY | ახალი შემთხვევითი გასაღები, მინიმუმ 32 სიმბოლო. იგივე ჩაწერე iPhone-ის „კავშირის გასაღებში“ |
| CREDENTIAL_ENCRYPTION_KEY | დამოუკიდებელი 64-სიმბოლოიანი hex გასაღები ბაზაში RS პაროლების დასაშიფრად. **მხოლოდ სერვერზე ინახება** |
| MYSQL_HOST | ბაზის მისამართი — ხშირად `localhost`, ან ჰოსტინგის მოცემული hostname |
| MYSQL_PORT | ჩვეულებრივ `3306` |
| MYSQL_DATABASE | cPanel-ში შექმნილი ბაზის სრული სახელი |
| MYSQL_USER | იმ ბაზის მომხმარებლის სრული სახელი |
| MYSQL_PASSWORD | MySQL მომხმარებლის პაროლი |
| HOST | `127.0.0.1` (თუ ჰოსტი სხვას ითხოვს, მისი მითითებით) |
| PORT | ჩვეულებრივ `3000`; თუ ჰოსტი თავად აწვდის PORT-ს, მისი მნიშვნელობა დატოვე |
| RS_INBOX_POLL | `0` — ხელით განახლება. `1` მხოლოდ მუდმივად გაშვებულ პროცესზე ფონური შემოწმებისთვის |
| RS_INBOX_INTERVAL_MINUTES | `10`, მინიმუმ `5` |
| BROWSERLESS_TOKEN | რეკომენდებულია cPanel-ზე: Browserless-ის API გასაღები. მითითებისას Chrome ჰოსტზე აღარ ეშვება და დისტანციური ბრაუზერი გამოიყენება |
| BROWSERLESS_URL | არასავალდებულო: Browserless-ის რეგიონი, ნაგულისხმევად `wss://production-sfo.browserless.io` (ევროპისთვის `wss://production-lon.browserless.io` ან `wss://production-ams.browserless.io`) |
| PUPPETEER_EXECUTABLE_PATH | არასავალდებულო: ჰოსტინგზე არსებული Chrome-ის სრული გზა |
| MYSQL_SSL_CA | არასავალდებულო: დისტანციური MySQL-ის CA სერტიფიკატის შიგთავსი, თუ TLS გჭირდება |
| EXPO_ACCESS_TOKEN | არასავალდებულო, Expo push-ისთვის; საჭიროებს ცალკე გამართულ iOS push კონფიგურაციას |

გასაღებების შესაქმნელად Terminal-ში, ამ საქაღალდიდან გაუშვი:

```sh
node generate-keys.cjs
```

მიღებული ორი მნიშვნელობა შეინახე Environment variables-ში. გენერატორი მხოლოდ აჩვენებს მნიშვნელობებს და ფაილებს არ ცვლის.
`CREDENTIAL_ENCRYPTION_KEY` შეინახე უსაფრთხოდ და **არსებული ბაზის გამოყენებისას აღარ შეცვალო**: მის გარეშე შენახული RS პაროლები ვერ გაიშიფრება. ბაზისა და ამ გასაღების სარეზერვო ასლები ცალ-ცალკე შეინახე.
`CONNECTION_KEY`-ის შეცვლისას iPhone-შიც განაახლე. აქ JWT_SECRET არ გამოიყენება: მიმდინარე აპი სერვერს საერთო Bearer გასაღებით უკავშირდება. გასაღები სანდო მომხმარებლებისთვისაა; მისი ყველა მფლობელი ამ სერვერის ყველა პროფილზე მიიღებს წვდომას.

## 4. Chrome და შემოწმება

დაქირავებულ პირთა სია იყენებს RS-ის პირდაპირ API-ს და Chrome არ სჭირდება. განახლებულ მობილურ აპში პროფილის „დაქირავებული პირები“ ღილაკით მიიღება სია, ძებნა და სტატუსის ფილტრი. ანგარიშს სჭირდება რეესტრის წაკითხვის უფლება; საჭიროებისას აპი ითხოვს RS-ის SMS კოდს. რეესტრის API ხელფასს არ აბრუნებს — ეკრანზე თანხა მიუწვდომელად აღინიშნება. SMS სესიები პროცესის მეხსიერებაშია; სერვერის გადატვირთვის ან სხვა პროცესზე მოხვედრისას თავიდან მიიღეთ სია.

### Browserless (cPanel-ისთვის რეკომენდებული)

თუ ჰოსტი Chrome-ს ვერ უშვებს, Environment variables-ში ჩაწერე `BROWSERLESS_TOKEN` და `PUPPETEER_SKIP_DOWNLOAD=true`, შემდეგ Run NPM Install და Restart. შემოწმება: `npm run check:browser` → `Browserless connect: OK` და `RS page: OK`. ამ რეჟიმში RS-ის მომხმარებელი/პაროლი Browserless-ის ბრაუზერში შეიყვანება, ანუ მესამე მხარის სერვისზე გადის.

ნორმალურ `npm install`-ზე Puppeteer ჩამოტვირთავს ჰოსტის Linux-ის Chrome-ს `.cache/puppeteer` საქაღალდეში. თუ ჩამოტვირთვა გამოტოვებული იყო, გაუშვი:

```sh
npm run browser:install
npm run check:browser
```

შემოწმება ჯერ Chrome-ს უშვებს, შემდეგ RS-ის შესვლის გვერდს ხსნის. **RS-ის მომხმარებლით არ შედის** და თანხების წარმატებით მიღებას არ ადასტურებს. შენახული მომხმარებლების ავტორიზაციის პრობლემა ჰოსტის გადატანით ავტომატურად არ სწორდება; საჭიროებისას RS SMS დადასტურებასაც ითხოვს.
Chrome-ის სისტემური ბიბლიოთეკების/sandbox-ის შეცდომაზე მიმართე ჰოსტინგს. თუ გამოყენებულია ჰოსტინგის Chrome (`PUPPETEER_EXECUTABLE_PATH`), npm install-ისთვის შეიძლება `PUPPETEER_SKIP_DOWNLOAD=true` მიუთითო.

ბრაუზერში გახსენი:

```text
https://api.domain.ge/health
```

უნდა მიიღო `status: ok`, `mode: server-client`, `database: mysql`. გაშვებისას MySQL შემოწმდება; `/health` მიმდინარე RS ავტორიზაციას არ ამოწმებს.
ბაზის მისამართი/სახელი ზემოთ MYSQL ცვლადებით განისაზღვრება; SQLite ფაილის გზა საჭირო არ არის.

## 5. iPhone-ის დაკავშირება

„სერვერის პარამეტრებში“:

- სერვერის მისამართი: `https://api.domain.ge`
- კავშირის გასაღები: ზუსტად სერვერის `CONNECTION_KEY`
- დააჭირე კავშირის შემოწმებას/შენახვას.

ახალი ბაზა ცარიელია. Mac-ის პროფილები ავტომატურად არ გადადის. დაამატე ისინი ახალი სერვერის არჩევის შემდეგ; თუ აპში ტელეფონზე დარჩენილი პროფილების გადატანის ღილაკი ჩანს, ის ახალი სერვერის არჩევის შემდეგ გამოიყენე. არც ერთი ამჟამინდელი RS პაროლი ან Mac-ის გასაღები ZIP-ში ჩადებული არ არის.

Passenger-ს შეუძლია უმოქმედო პროცესების გაჩერება/რამდენიმე პროცესის გაშვება, ამიტომ ფონური შემოწმება ნაგულისხმევად გამორთულია. ერთი მუდმივი პროცესის მხარდაჭერის გარეშე RS_INBOX_POLL=0 დატოვე; პროფილზე ხელით განახლება მუშაობს. APNs/push მზადყოფნა ამ სერვერის ZIP-ით არ იცვლება.
